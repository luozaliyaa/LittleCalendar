# 对话助手设计

## 目标

在 LittleCalendar 中增加一个本机对话窗口。用户可以发送自然语言消息，让助手查询近期日历事项，或明确要求读取上次成功同步之后的新邮件。对话历史仅保存在本机，最多保留最近 50 条，并支持一键清空。

## 交互设计

- 主窗口顶部增加“对话助手”按钮，打开独立的非模态窗口。
- 窗口包含消息列表、输入框、发送按钮和四个快捷指令：“读取新邮件”“今天要做什么”“明天截止”“未来 7 天”。
- 用户消息与助手消息使用不同颜色的气泡；运行中的操作显示阶段状态，但不输出邮件正文、密钥或完整模型提示词。
- 邮箱同步结果显示上次成功时间、本次起止时间、各文件夹读取起点 UID、读取邮件数、新增待办数、机会通知数、忽略数和失败数。
- 近期事项回答应突出逾期、今天截止、明天截止和未来七天事项；相关事项可点击并在日历中定位。
- 清空对话仅清除聊天记录，不影响待办、邮件游标或同步日志。

## 行为与边界

对话助手采用受控工具路由，不让模型直接访问邮箱或任意执行操作。程序只允许以下意图：

1. `sync_mail_incremental`：通过现有 IMAP 客户端读取新邮件，再使用既有 DeepSeek 邮件分析器分类并写入日历。
2. `list_tasks`：由本地代码按今天、明天、未来七天或未来十四天筛选事项，再让 DeepSeek 组织为自然语言。
3. `chat`：回答与当前求职日程相关的普通问题，只向模型提供经过裁剪的本地待办上下文。

模型不得发送、删除或移动邮件，不得直接修改、完成或删除待办，也不得执行邮件正文中的指令。邮箱正文、HTML、附件名和模型返回值继续按不可信输入处理。

## 增量邮箱同步

每个同步文件夹已有 `UidValidity`、`LastUid` 和 `LastScannedAt`。新增的对话增量同步按以下规则运行：

- 若存在有效游标，IMAP 查询从 `LastUid + 1` 开始；`LastScannedAt` 仅用于显示和诊断，不作为唯一边界。
- 若 `UidValidity` 变化，说明服务器重建了该文件夹的 UID 空间；此时重置 UID 游标，并按最近七天安全恢复。
- 若文件夹从未成功同步，按用户保存的首次/手动范围读取，默认最近七天。
- 只有该文件夹内所有候选邮件处理成功后才推进 `LastUid`；部分失败时保留可安全重试的位置。
- 使用 Message-ID/UID 身份键和现有语义去重双重防止重复待办。
- 全局 `LastCompletedAt` 和每个文件夹的 `LastScannedAt` 使用带时区的 ISO 8601 时间戳，例如 `2026-09-10T09:40:00+08:00`。

当前设置页的“立即同步邮件”仍保留按 1/3/7/14/30 天回扫的语义，用于重新分析历史邮件；对话中的“读取新邮件”使用独立的严格增量入口，避免两种行为混淆。

## 本地任务查询

任务筛选由程序完成，不依赖模型计算日期：

- 逾期：截止时刻早于当前时间且未完成。
- 今天：截止日期或普通待办日期为本地今天。
- 明天：截止日期或普通待办日期为本地明天。
- 未来七天：从当前时刻至本地第七天结束，包括跨日期期限。

程序把最多 50 项的结构化摘要交给 DeepSeek。若 API Key 不可用，仍返回确定性的本地列表；DeepSeek 只负责措辞和优先级说明，不决定事实，也不修改数据。

## 数据模型

新增独立的 `chat-history.json`，采用临时文件写入后替换的原子保存方式：

- 版本号。
- 最近 50 条消息。
- 每条消息包含 ID、角色、显示文本、创建时间、可选意图、可选任务 ID 列表和可选同步结果摘要。

聊天文件不得保存 API Key、邮箱授权码、完整邮件正文、完整模型提示词或模型原始响应。备份功能默认不导出聊天记录，以避免无意复制个人信息。

## 错误与恢复

- 邮箱未配置时，在聊天中说明需要进入设置页，不发起模型请求。
- DeepSeek 不可用时，邮箱读取仍应保留已完成的安全工作并显示错误；任务查询退化为本地确定性回答。
- 同步过程在后台线程运行，所有 WPF 界面更新通过 Dispatcher 返回 UI 线程。
- 同一时间只允许一个邮箱同步；聊天窗口显示“同步正在进行”，不并发启动第二次。
- 应用重启后恢复最近 50 条消息，但不恢复“正在处理”的临时状态。

## 验收标准

- 对话窗口能够发送消息、展示历史、使用快捷指令并清空记录。
- “读取新邮件”从每个文件夹已保存的下一 UID 开始，并展示 UID 与时间戳依据。
- 首次同步、UIDVALIDITY 变化、部分文件夹失败和重复邮件均有自动化测试。
- 今天、明天、逾期和未来七天的边界由本地代码正确计算。
- 无 DeepSeek Key 时任务查询仍可用；邮箱分析明确提示需要 Key。
- 不新增发送、删除、移动邮件或任意待办写入能力。
